## 처리량과 응답 시간
### 응답 시간
사용자의 요청을 처리하는 데 걸리는 시간을 의미한다.
(서버에 연결, 서버로 데이터 전송, 서버 실행, DB 연결&실행, API 응답 등...)

클라이언트가 서버로 요청을 보내는 과정은 크게 2단계로 이루어진다.
1. 서버에 연결: TCP를 이용해서 서버에 연결한다.
2. 데이터 전송: 정해진 규칙(프로토콜)에 따라 데이터를 서버에 전송한다. 예를 들어 HTTP 프로토콜에 따라 POST 방식으로 JSON 데이터를 보낼 수 있다.

서버는 응답 데이터를 전송할 때 서버와 연결된 소켓을 이용한다.
응답 시간은 다음과 같이 2가지로 나누어 측정하기도 한다.

#### TTFB(Time to First Byte)
응답 데이터 중 첫 번째 바이트가 도착할 때까지 걸린 시간

#### TTLB(TIme to Last Byte)
응답 데이터의 마지막 바이트가 도착할 때까지 걸린 시간

응답 데이터의 크기가 작다면 TTFB와 TTLB의 차이가 크지 않다.
하지만 파일 다운로드처럼 전송할 데이터가 크거나 네트워크 속도가 느리면 차이가 커질 수 있다.
따라서 서버 성능을 올바르게 평가하려면 데이터 특성이나 네트워크 환경을 고려해 둘 중 적절한 지표를 선택해 측정해야 한다.

응답 시간은 1초보다 짧을 때가 많아, 밀리초 단위를 사용한다

서버 개발자는 주로 서버의 처리 시간을 확인한다. 서버 처리 시간은 다음과 같은 요소를 포함한다.
- 로직 수행(if, for 등)
- DB 연동(SQL 실행)
- 외부 API 연동
- 응답 데이터 생성(전송)

이 중에서도 DB 연동과 외부 API 연동이 큰 비중을 차지한다.
- 전체 처리 시간: 348ms
- API 연동1(외부 네트워크에 존재하는 API 호출): 186ms(53%)
- API 연동2(내부 네트워크에 존재하는 API 호출): 44ms(13%)
- DB 연동(SQL 실행 6회): 101ms(29%)
- 로직 수행: 17ms(5%)

필자가 경험한 서비스에서 실제 한 요청의 처리 시간을 측정한 결과를 보면 API 연동 2번만으로 전체 처리 시간의 66%나 차지한다. DB 연동도 29%를 차지한다.
API 연동이 없는 경우라면 DB 연도이 전체 실행 시간의 70~80% 이상을 차지한다.
즉, 응답 시간을 줄일 때 DB 연동과 API 연동 시간에 집중한다.


### 처리량
처리량은 단위 시간당 시스템이 처리하는 작업량을 의미하는데, 흔히 TPS나 RPS로 처리량을 나타낸다.
TPS는 초당 트랜잭션 수(transaction per second), RPS 초당 요청 수(request per second)의 약자이다.
서버의 성능 지표를 표현할 때 TPS나 RPS를 구분 없이 혼용하기도 한다.(이 책에서는 TPS를 사용)

응답 시간의 증가를 방지하려면 2가지 방법을 고려해야 한다.
- 서버가 동시에 처리할 수 있는 요청 수를 늘려 대기 시간 줄이기
- 처리 시간 자체를 줄여 대기 시간 줄이기

두 방법을 적용하면 TPS를 높일 수 있다.

TPS를 확인하는 가장 간단한 방법은 스카우터, 뉴렐릭, 핀포인트와 같은 모니터링 툴을 사용하는 것이다.
엘라스틱 서치 같은 별도 시스템에 접근 로그를 수집한 뒤 집계하면 된다.


## 서버 성능 개선 기초
### 병목 지점
트래픽이 증가하면서 성능 문제가 발생하는 주된 이유는 시스템이 수용할 수 있는 최대 TPS를 초과하는트래픽이 유입되기 때문이다.

시스템이 제공할 수 있는 최대 TPS를 높이지 않으면 증가하는 트래픽을 적절히 처리할 수 없다.
